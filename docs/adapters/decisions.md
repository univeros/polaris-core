- 2026-09-10 · WP0 · The proof of an adapter is the unchanged functional suite plus the 184 fixtures through the framework's real HTTP kernel, selected by `POLARIS_HARNESS` (spec §3.7), with an explicit per-adapter allow-list of transport headers the framework adds to every response. · Reason: "no adapter changes a response" has to be checked by the same comparison that froze the contract; the allow-list keeps the framework's transport layer out of it without weakening the rest. · Rejected: a second, adapter-specific fixture set (would drift); stripping the framework's headers in the adapter (fighting the framework for the test's sake).
- 2026-09-10 · WP0 · Schema in a framework: the adapter's migration or command runs `SqlSchema` for the connection's dialect and seeds the catalog; no translation into Blueprint, Doctrine schema or Yii migrations. · Reason: one source of DDL, proven by `schema:diff`; a translation would be a second schema to keep equal. · Rejected: `schema:export --target=laravel|doctrine` emitting builder code (task 1 left the targets to the adapters; this decides what they are).
- 2026-09-10 · WP1 · Laravel routes: one named Laravel route per manifest endpoint (`polaris.auth.login`, ..., `PolarisController` for all), no catch-all. · Reason: a catch-all under `path_prefix: /` matches everything registered after it and shadows the application's own routes; per-endpoint routes give `route:list` and `route()` for free and leave unknown paths to the application's 404. - 2026-09-10 · WP1 · What Laravel's transport adds and the contract comparison ignores: the `cache-control` header (HttpFoundation computes `no-cache, private` for every response without one), declared by `Harness::transportHeaders()`; and the `Content-Type: text/html; charset=utf-8` HttpFoundation sets on a body-less response Polaris sent without one (the rate limiter's 429), which the harness removes before comparing, because PHP's SAPI sends that same default from any host and the recorded fixtures never saw a wire. Everything else is byte-identical: 184 fixtures, 1,201 steps, through the HTTP kernel, on SQLite locally and PostgreSQL in CI.
- 2026-09-10 · WP1 · The generated migration runs with `$withinTransaction = false`. · Reason: `PdoAdapter::transaction()` opens its own transaction on the same PDO handle (the seeder runs inside one); nested inside the migrator's it would fail with "There is already an active transaction". - 2026-09-10 · WP1 · Secrets: `config/polaris.php` reads `POLARIS_APP_KEY` and falls back to Laravel's `APP_KEY` (`base64:` plus 32 bytes, so at least 32 bytes long); every Polaris key is HKDF-derived under its own context, so sharing the master key with Laravel's encrypter exposes nothing. PEM keys come from `AUTH_JWT_*_FILE` paths (relative to the base path) or the `AUTH_JWT_*` values.
- 2026-09-10 · WP1 · Core friction fixed in `polaris/cli`: `SchemaDiffCommand` and `DoctorCommand` take optional providers (a connection, the `Secrets` and the `AuthConfig`) so a host's console can run them on its own configuration; without them they read `--dsn`/`POLARIS_DSN` and the environment as before. `Database::dialectOf(PDO)` detects the dialect of a handle. The four commands appear in artisan as `polaris:schema:export`, `polaris:schema:diff`, `polaris:manifest`, `polaris:doctor` (renamed with `setName()`, added through `Artisan::starting`, as plain Symfony commands).
